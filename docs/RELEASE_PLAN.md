# Release plan

**One handover.** Schools receive the complete NavShiksha once, at go-live — not a half-built system that grows in front of them. R1, R2 … are internal milestones. Each one is finished end to end before the next starts:

- database changes (additive migrations only), API, staff screens, parent app and the Unified portal for that area;
- behaviour tests, including the database guarantees;
- seed data so every role can try it;
- a demo to NES, signed off before moving on.

Nothing from a milestone is "coming soon" inside the product. A module appears in the app only when it works.

## Build order after the module review (15 Oct 2026)

The module review (`../NES_Module_Review.html`) checked every module against real school work. Inside the build, the order is now:

1. Timetable rebuild: bell timings and breaks, special days, teacher absence and proxies, generator. **Done.**
2. Foundations used by every module: settings inherited NES → Command → school, duties (timetable coordinator, exam in-charge…), approval chains, attachments, import/export/print, templates and Hindi. **Done:** settings, duties, approval chains, the access policy (who sees what of a child), class teachers with co-class teachers. **Server only so far:** attachments, student import/export. **Still to do:** their screens, print templates, Hindi.
3. Daily school upgrades: attendance (correction window, working days, low-attendance alerts), homework (attachments, submissions, overload control, digest), leave and gate pass, calendar set-up.
4. Records upgrades: online admissions with waitlist, promotion and certificates with QR verification, exam screens, date sheet, invigilation, report cards.
5. Fees upgrades. Done: arrears for backdated revisions (with the next instalment, on a date, or spread), additional charges (compulsory or opt-in, seats and waiting list, refund date, excusing, cancellation, payouts to CBSE or operators), credit used against dues, refunds with approval. Still to do: late-fee rules, counter collection screen, concession requests, settlement matching. Then staff and payroll (R4).
6. Communication upgrades (attachments, acknowledgements, scheduled sends, SMS fallback) and grievances.
7. Operations (R5), NES governance (R6), production readiness and VAPT (R7).

Schools still receive the complete system once, at go-live.

## Definition of done (every milestone)

1. Every new table has keys, foreign keys, CHECKs, the audit trigger, and immutability where records are financial or official.
2. Every route checks role and org scope; parents only ever reach their own children.
3. Tests cover the rules that protect data, and the whole suite passes.
4. Each role in the README can complete the new flows in the browser without errors on desktop and phone.
5. `npm audit` shows no known vulnerabilities.
6. Docs updated: README (how to try it) and ARCHITECTURE (any new rule).
